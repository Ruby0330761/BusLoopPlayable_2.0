## 1. 目标与本稿推荐

在场景编辑器中增加「倒计时挑战」设置，让素材制作人员可以为当前关卡选择是否启用限时玩法、设置总时长和临近结束警示，并让编辑器试玩与导出成品采用一致规则。

本稿建议：旧关卡默认关闭；开启后默认 30 秒；第一次成功发车后按真实可玩时间倒数；最后 10 秒出现红光；每关独立计时；归零统一进入现有失败流程，Game Over 与 Retry 沿用当前规则，不新增到时行为选项。

这里的倒计时是**当前整关的限时挑战**，不属于某辆消防车或救护车的专属机制。

## 3. 当前编辑器逻辑与缺口

1. 当前没有整关倒计时开关、可配时长或顶部时间显示。`game.time` 是随游戏倍速改变的模拟时钟，不能直接作为本需求的真实秒数。
2. 右侧场景面板按当前关卡自动保存浏览器调参；关卡布局保存写入服务端文件，两者不同。导出时会携带当前调参，关卡 JSON 导出可以附带这些参数。
3. 当前普通失败、Game Over 和 Retry 已存在；Retry 重建首关并重置会话。固定换关和选关进入新关也会重建游戏模型。代码核对：`src/scene-tuning.js:151`、`src/scene-editor.js:646` 的 `gameOver.retryEnabled` 控制「启用重试按钮」；`src/main.js:2599` 的失败面板流程直接显示 Game Over，目前没有控制整个 Game Over 显示与否的总开关。不能把 Retry 开关解释为面板总开关。
4. 救护车现有步数限制继续有效。消防车的 `timeLimit` 虽可编辑和透传，当前并没有整关倒计时语义，不复用为本需求开关。
5. 当前有效操作返回 `ok` 可能只代表隐藏车揭示；本稿把「成功发车」限定为确实派往车位。本次不修改既有 CTA 操作次数的计数方式。

## 4. 编辑器开关与配置项

入口：右侧「关卡」分类，新增独立折叠组 **倒计时挑战**。不新增顶层分类。

| 界面字段 | 控件与可选项 | 已确认默认值 | 校验与联动 |
| --- | --- | --- | --- |
| 启用倒计时 | 开关：关闭 / 开启 | **关闭** | 关闭时隐藏试玩中的时间和红光，不启动限时逻辑；其他配置保留但不可编辑 |
| 倒计时时长（秒） | 整数输入 | **30** | 1–5999 秒，步长 1；不能用 0 代替关闭 |
| 临近结束红光 | 开关：关闭 / 开启 | **开启** | 仅在总开关开启时生效；关闭后时间仍正常倒数 |
| 红光提前时间（秒） | 整数输入 | **10** | 1–总时长；红光关闭时不可编辑；缩短总时长导致超限时同步降至新总时长并显示更新值 |

界面辅助说明：`首次成功发车开始计时；倍速不影响；后台暂停；重试重新计时。`

不增加「仅显示计时、不限制玩法」、计时速度倍率、不同起算方式、到时行为下拉、倒计时专属的 Game Over / Retry 开关等额外选项。失败展示复用现有配置。

## 5. 计时规则

### 5.1 开始与显示

- 开启后，在游戏画面可见时显示完整时长；加载和前贴期间不消耗时间。
- **第一次成功派出车辆到车位后启动**。空白点击、被阻挡点击、车位已满、点击倍速、拖动画面、只揭示隐藏车，以及被开场引导拦截的点击均不启动。
- 本次操作若已使原玩法进入失败或 CTA 结束流程，则不再启动计时。
- 时间格式为 `MM:SS`，例如 30 秒显示 `00:30`，90 秒显示 `01:30`；剩余秒数向上取整，归零显示 `00:00`，不会出现负数。

### 5.2 真实时间与暂停

- 使用真实经过的可玩时间；x1/x2、长按加速、传送带速度均不改变倒计时速率。
- 页面进入后台或广告宿主报告不可见时暂停，恢复时继续剩余时间，不补扣隐藏期间的时间。
- 前贴、开场强制锁输入、关卡过场、选关等待、布局或空间编辑工作区期间暂停倒计时。只有视觉提示且不锁输入的引导不暂停。
- 暂停的是本功能的扣秒与警示动画，不通过冻结整个游戏模拟来等待引导结束，以免引导计时本身无法结束。现有其他玩法的模拟语义不在本次改动范围内。
- 低帧率时仍按真实经过时间扣秒，不能因为每帧模拟时间上限而延长挑战。

### 5.3 红光

- 仅在已起算且剩余时间大于 0、不超过预警秒数时，显示四周半透明渐变红光。
- 沿用参考的缓入缓出效果，中心操作区保持清晰，红光不拦截点击。
- 暂停时冻结动画；恢复后继续；关闭功能、胜利、失败或进入结束流程后立即停止并隐藏。
- 系统启用减少动态效果时使用静态弱红光。

### 5.4 换关与重试

- 每次进入新关均恢复完整时长，等待本关第一次成功发车；固定下一关和玩家选出的下一关都遵守此规则。
- 多关导出暂用**整包同一份倒计时配置，各关重新计时**，不是整段试玩共享一个总秒数。本期不增加每个 stage 单独配置的入口，也不读取其他关卡的浏览器调参来拼接。
- Retry 沿用现有重开范围，回到原本应重开的首关；清理旧轮次超时状态与回调，恢复满时间和未起算状态。
- 普通胜利或原玩法失败发生时立即结束本轮倒计时，不覆盖原有结果。

## 6. 到时行为与优先级

### 统一复用现有失败流程

时间归零后停止计时与红光，冻结本局车辆操作，进入与普通关卡失败相同的 Game Over 流程；倒计时本身不额外发起商城跳转。

- Game Over 标题、遮罩、Logo 和 CTA 沿用既有失败表现与参数，不另建倒计时失败面板。
- `gameOver.retryEnabled = 1` 时显示既有 Retry，点击后重新开始；为 `0` 时不显示 Retry，Game Over 的其他表现仍按原规则执行。
- 不新增 Game Over 面板总开关，也不改变现有 Retry 开关的语义、默认值或位置。
- 不引入参考素材的商城返回状态、返回标记或延迟显示失败流程。

### 同时发生事件的约定

- 当前帧原玩法已判定胜利、失败或已触发既有 CTA 结束流程时，先尊重该结果，停止本倒计时，不追加另一次超时处理。
- 原玩法仍在进行且剩余时间归零时，才进入一次超时失败；重复帧和可见性变化不得重复结算。
- 本功能不改原胜利条件、车位拥堵失败、救护车步数失败、成功操作次数与商店链接。

## 7. UI 与交互需求

- HUD 沿用参考的蓝色闹钟与白色数字，放在实际游戏内容区顶部居中；右侧给倍速按钮留出空间。参考素材为 `assets/images/timer-frame.png`，1001×392 PNG。
- 竖屏、横屏和有留边的宽屏均以游戏内容区定位，避免遮住倍速按钮或超出可见区。倍速关闭时闹钟仍能独立正常定位。
- 闹钟是显示层，不可点击，不抢占车辆或按钮输入；不在本期增加闹钟位置、尺寸、颜色和素材替换控件。
- 总开关关闭时，依赖字段置灰并保留上次有效值。红光关闭时，仅预警秒数字段置灰。
- 时长输入在失焦或 Enter 确认后生效；确认总开关或时长的改变会保存配置并自动重开当前试玩预览，避免旧局中途改变规则。界面对此给出提示；输入过程中不反复重开。
- 红光开关和预警秒数可即时预览，无需重开。
- 空值、小数、非数字或越界输入显示就近中文错误；保留上次有效配置，错误未修复前不能导出。总开关关闭后的不生效字段不阻止正常导出。
- UI 分流：增加场景参数组和参考 HUD，关键状态、联动和错误反馈均由本稿列出供确认；实现前在开发方案中补齐轻量 UI 规格，不借此扩大为编辑器界面重设计。

## 8. 保存、兼容与导出

- 按当前关卡保存浏览器配置；刷新和切关后回到各自设置。配置不能只保留在内存。
- 关卡 JSON 的现有调参导入/导出、单平台及全平台导出均保留本功能设置；实际构建后的时长、红光和原有失败展示配置与导出时一致。
- 老关卡、老 JSON 和旧浏览器缓存缺少配置时均默认关闭，不自动迁移成 30 秒挑战。
- 不把新设置回写为 Unity 的消防车时间或救护车步数字段。
- 计时配置支持现有 BL / BFT 品牌输出，不覆盖品牌资源、商店目标或导出命名。
- 开启时，最终包所需闹钟素材必须内嵌或包含在对应平台包内，不请求桌面参考目录；关闭时不加载该额外图片。
- 本轮没有部署、线上写入、第三方依赖安装或升级；确认后仍需对最终成品做必要验证，平台上传及真机验收单独记录。

## 9. 范围边界

范围内：总开关、秒数配置、红光开关与预警秒数、复用既有失败流程及 Retry 开关、参考 HUD、暂停/重试/换关、旧配置兼容、配置随导出传递、对应回归验证。

## 10. 验收标准

| 编号 | 场景 | 可观察结果 |
| --- | --- | --- |
| AC01 | 老关卡或关闭功能 | 无时间 HUD、无红光、无超时结算，原玩法与 CTA 规则不变 |

## 11. 已确认的产品决定

1. 采用上述配置项及默认值：旧关默认关闭、开启后 30 秒、红光开启并提前 10 秒，总时长允许 1–5999 秒。
2. 采用「首次实际发车起算、真实时间不随倍速、每关重新计时」的规则；隐藏车揭示不起算，整包暂不分 stage 设置。
3. 按本次补充，归零复用现有失败流程，Retry 沿用 `gameOver.retryEnabled`，不新增到时行为选项或 Game Over 开关。当前已核对不存在整个 Game Over 显示总开关。
