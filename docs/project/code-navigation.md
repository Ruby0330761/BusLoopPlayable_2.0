## File Responsibilities

### Root/config

- `index.html`: DOM shell for the playable. Owns `#app`, `#stage`, `#game-canvas`, branding image/text overlay, message overlay, end panel, reset button, the failure card's `#game-over-retry` button (sibling of the overlay, so its "ready" fade is a `+` rule), and `#scene-editor` mount.
- `.gitattributes`: preserves exact bytes in imported Footage8/9/10 Unity source directories so Git newline conversion cannot invalidate their provenance hashes.
- `package.json`: npm metadata, Vite scripts, `node --test` test script, and dependency list.
- `scripts/package-applovin-single-html.mjs`: AppLovin packaging utility. Reads Vite `dist`, inlines built JS/CSS and `/assets/...` files as data URIs, and writes `artifacts/applovin/index.html`.
- `scripts/export-playable-package.mjs`: Package-only multi-platform exporter. Applies the current editor tuning in an isolated temporary workspace, stages and compresses any legacy custom pre-roll, builds platform-native HTML/ZIP deliverables, builds every selected branding set through its variant (`BL` = one package carrying both store icons, `BFT` = one package with its own art/logo/links), runs the bundled local rules, and publishes only passing artifacts. Delivery naming is identical across sets and always comes from the exported tuning; a branding set never rewrites the requirement code, requester, or appends a suffix. The archive mirrors the NAS hand-over layout — `<requirement>-<material>/<AL|GG|FB|MT|MO|TT|UN>/<file>` — via `buildDeliveryFolderName`/`resolveChannelFolder`, and `manifest.json` is written beside the archive rather than inside it because the NAS uploader rejects files it cannot assign to a channel.
- `scripts/pre-roll-transcoder.mjs`: FFmpeg-backed custom pre-roll transcoder. Produces browser-compatible H.264/AAC MP4s under the editor export budget and keeps legacy uploads from bypassing compression.
- `scripts/repair-legacy-playables.py`: Standalone repair tool for artifacts exported before the FBX data-URI fix and the Mintegral CSS inlining. Patches `index.js`/single-HTML text in place (URL modifier + internal resource-path scheme), inlines `style.css` into Mintegral HTML, backs up each file first, and is idempotent (skips already-fixed artifacts).
- `scripts/check-playable-runtime.mjs`: Project-level Chrome/CDP runtime gate for exported HTML, ZIP, and directory artifacts. Supplies platform host mocks, waits for BusLoop startup/loading completion, checks visible canvas pixels, and rejects runtime, console, or resource errors.
- `scripts/build-level-contact-sheet.mjs`: Static level contact sheet generator. Reads level documents (local `artifacts/web-levels` by default, or live remote over HTTP with `--remote`) and writes one self-contained HTML page with every level's top-down thumbnail. Rendering itself lives in `src/level-layout-thumbnail.js`.
- `src/level-layout-thumbnail.js`: Pure top-down layout renderer shared by the contact sheet and the editor's level overview, so a thumbnail means the same thing in both. Owns vehicle footprint size by seat count, atlas colour lookup with per-vehicle `colorOverrides.body` taking precedence, yaw-rotated footprints, the cabin-roof + heading-arrow car glyph (`vehicleCabinRect`, `vehicleArrowPoints`), parking-bay outlines, bounds/projection, and the empty-level and hidden/turning-vehicle markers. Cars are drawn through the shared authored→runtime transform by default (pass `transform: null` for raw authoring space) and at the playable's model size via `resolveDisplayVehicleSize`, so a card matches the phone preview. Deliberately excludes conveyor spline points from the frame — they sit ~20 world units away and would squash the car field.
- `src/official-levels-picker.js`: In-editor official in-game level picker. Owns the chapter tabs, search, thumbnail cards, the “not importable yet” disabled state with its reason, the operator-header import request, and the import→switch handoff. Deliberately separate from the authoring overview: this lists the game's shipped assets, not levels that already exist in the authoring volume.
- `src/level-overview.js`: In-editor level overview overlay. Renders every level as a thumbnail card with search (name, key, owner, belt, counts), sort (number / name / created / vehicle count), and click-to-switch through the same commit path as the dropdown. Reads `/__level-authoring-overview`, and names a stale selection explicitly when the stored key no longer exists.
- `scripts/check-applovin-package.mjs`: AppLovin static upload precheck for `artifacts/applovin/index.html`, including size, single-file, inline-resource, WAV, remote URL, and MRAID CTA checks.
- `scripts/apply-scene-tuning.mjs`: Applies exported editor tuning JSON from `artifacts/scene-tuning.json` (or `--input`) into `src/scene-tuning.js` and synchronizes `artifacts/selected-level.txt` before production packaging.
- `scripts/start-remote-editor.mjs`: Programmatic Vite startup for the deployed editor container, including fixed remote host/port settings and explicit lifecycle error logging.
- `scripts/spatial-conveyor-importer.mjs`: Standalone Node importer for the BusLoop `ConveyorBeltTemplate` spatial-track family. Merges prefab overrides with bundled Dreamteck/template support, embeds required textures, and writes one removable JSON package per imported prefab under `artifacts/spatial-conveyors/`.
- `scripts/unity-level-parser.mjs`: Pure Unity level-asset parser. Owns the YAML section/record readers, quaternion-to-yaw conversion, passenger-queue and depth decoding, the Unity collision/garage baselines, and the reference-playable queue/vehicle overrides. Shared by the catalog extraction CLI and the official level browser so both read an asset the same way; no filesystem access.
- `scripts/official-levels.mjs`: Official in-game level library. Owns chapter-folder discovery under `official-levels/`, the chapter+number→`level<number>` key namespace (guide levels take a `9` marker), readable display names, per-chapter summary caching keyed on file size/mtime, thumbnails through the shared renderer, and path-safe asset lookup. Levels it cannot import yet (unsupported container types, seat/passenger mismatch) still render with the blocking reason, so they never silently vanish.
- `scripts/unity-level-importer.mjs`: Validates editor-imported `.asset` Unity YAML with arbitrary upload names, derives a canonical `level<number>` identity, rejects unsupported mechanisms and invalid vehicle/container/queue references, rolls back failed catalog updates, and stores accepted sources under `artifacts/unity-level-sources/`.
- `scripts/level-ownership.mjs`: Per-level write ownership for the authoring service. Owns operator-name normalization (whitespace collapsed, case-insensitive comparison key so one person cannot become two owners), the `artifacts/level-owners.json` sidecar registry shape, and `resolveLevelWrite`, which decides claim/write/refuse. It is a guardrail against two operators overwriting each other's levels, not authentication: the name comes from the browser. A level with no registry entry is read-only: it is only taken over through the explicit claim endpoint, never as a side effect of saving. Deleting a level releases its owner so a later import is not blocked.
- `scripts/level-name-registry.mjs`: Shared level display-name identity for the authoring service. Normalizes the decorations that mean “same level” (Finder copy suffixes like ` (1)`, auto import labels like ` (level12.asset)`) and finds whether a candidate name collides with another level in the merged list.
- `scripts/generate-active-spatial-conveyor.mjs`: Reads the baked conveyor selection, validates the matching imported JSON package, and generates the single spatial conveyor payload included in production builds.
- `tools/spatial-conveyor-import-support/bus-loop-spatial-v1/`: Editor-owned Unity/Dreamteck support package used by the spatial importer; imports do not read the external BusLoop Unity project.
- `tools/unity-vat-export/Packages/manifest.json`: Unity package manifest for the VAT export helper project.

### Runtime source

- `src/main.js`: Browser entry point. Wires `BusLoopGame`, `SceneView`, `GameAudioController`, the selected platform bridge, and `createSceneEditor`; handles saved tuning migration, responsive branding image/text positioning, text fitting and dragging, HUD sync, reset, long press speed-up, animation frame loop, and `window.__busLoop` QA/debug API.
- `src/pre-roll.js`: Pre-roll video controller. Coordinates muted autoplay, optional trusted-gesture sound enablement, game readiness, watchdog fallback, fade transition, and visibility pause/resume.
- `src/platform-bridge.js` and `src/platform-bridges/*.js`: AppLovin baseline plus build-selected Google Ads, Meta, Unity Ads, Mintegral, Moloco, and TikTok lifecycle/CTA adapters. The AppLovin bridge also owns the Axon challenge funnel semantics (`challengeProgress`/`challengeSolved`/`challengeFailed`/`challenge retry`, solved-state suppression, and the pre-CTA `CHALLENGE_STARTED` backfill); other bridges expose the same methods as no-ops.
- `src/audio-controller.js`: Runtime audio bridge. Owns Unity-named sound config playback, WebAudio unlocking/preloading, random clip choice, game-event de-duping, boarding playback, per-sound start delay, and the editor volume multiplier (level volume x scale, so a slider at 1 keeps the Unity balance).
- `src/game-model.js`: Pure gameplay state machine. Owns vehicle click handling, blocker checks, station assignment, route progress, conveyor/queue passenger flow, boarding events, win/fail checks, snapshots, and subscriptions. Also owns `distributeQueuesAcrossLanes`, the round-robin split that fills every visible queue lane when a level was authored for a belt with fewer lanes than the artwork shows, gate-queue advancement, elevator floor promotion, and the surplus-seat departure that lets a colour with more cars than passengers still finish.
- `src/mechanic-containers.js`: Pure geometry for the two container mechanisms only the newer level pack uses. Owns gate-queue path sampling/ordering and nose-to-tail layout (which reproduces the authored car positions exactly), plus the elevator floor helpers. No THREE, no DOM, no game state.
- `src/vehicle-collision.js`: Unity-style runtime collision context. Owns per-vehicle collision sizes, current-pose oriented boxes, drive-out graph decisions, direct candidates, and edge contact points.
- `src/level-data.js`: Small runtime boundary that exports colors and the mutable live `LEVEL_1` binding backed by the current generated session level. It completes a level's colour-atlas slots on activation, so a level built against a pre-supplement catalog cannot fall back to blue for black/white cars.
- `src/color-atlases.js`: Canonical 26-slot colour-atlas table plus `resolveColorAtlasPaths`/`isColorAtlasTableComplete`. Owns the colour-index→atlas mapping independent of catalog age; slots 11-16 stay null for the special mechanism vehicles.
- `src/level-audio-config.js`: Canonical per-level sound table (`bus_hit`, `passenger_up`, `bus_full`, `vehicle_tap`) plus `resolveLevelAudioConfig`/`isLevelAudioConfigComplete`. Owns which clips and volumes a level's audio events play, independent of catalog age; a name the level already supplies keeps its own clips and balance. Mechanism sounds stay in `src/mechanism-resources.js`.
- `src/level-session.js`: Pure session state. Owns current level order, level-scoped successful-vehicle de-duplication, shared CTA/install count, win advancement, the pending-choice gate a stage can end on, chosen-map insertion, and full-session reset (which drops the picked map).
- `public/assets/applovin/stage-choice/`: Rendered 512x782 stage cards (top belt strip, bottom vehicle field) used by the post-stage picker. Generated from the real scene and inlined by the packager, so they must stay in the export asset pass.
- `src/playable-session-config.js`: Playable session document schema and validation. Owns stage normalization (level key, per-stage conveyor/background/parking-spot count, opening guide and entry banner, HUD labels), stage id/level-key bounds, per-version export naming, and the stage-override merge used by the renderer.

### Conveyor layout subsystem

- `src/footage8-conveyor.js`: shared Footage8/9/10 model loading, display/path transforms, road-height sampling, continuous-motion runtime config, queue merges, and editor-only boarding markers. `src/footage9-conveyor.js` / `src/footage10-conveyor.js` select independent layouts/defaults; their default boarding zones come from the supplied prefab exit ranges.
- `src/footage8-surface.js`: indexed road-surface height lookup and the Footage8 boarding landing/stairs/ramp. `test/footage8-conveyor.test.js` covers source-path extraction, geometry alignment, queue continuity, fill speed, passenger conservation, and boarding.
- `scripts/extract-footage8-conveyor.mjs` generates mesh/layout data from stored source assets. `scripts/extract-footage9-conveyor.mjs` exposes the shared Footage9/10 Unity-package importer; `scripts/extract-footage10-conveyor.mjs` is its Footage10 CLI. Both CLIs accept an optional `.unitypackage` path, or regenerate from repository sources when omitted. Inputs/manifests and inherited `Paths.prefab` live in `artifacts/footage<N>-source/`; outputs are `src/generated-footage<N>-layout.js` and `public/assets/unity/conveyors/footage<N>/`.
- All three model conveyors have editor options and `<id>Conveyor` tuning. Footage9/10's shared field groups live in `src/scene-editor.js`; the AppLovin packager whitelists reachable models/textures. `test/footage-model-conveyors.test.js` covers supplied source hashes, transforms, surface coverage, independent boarding zones, session/editor availability, continuous fill/conservation, and rendered entry poses.

- src/conveyor-layouts.js: generated catalog for DualQueue2/3/5/10 art plus the `ConveyorBelt_Footage*` variants (`starLoop` / `heartLoop` / `catLoop`), closed/queue splines, capacities, exit ranges, and maximum pools. The three Footage belts use their native Unity prefab spline and queue points mapped into scene space by `(0.826305 * x - 0.004829, 0.826305 * z + 14.2367365)` and share the `{ x: 0, y: -0.045, z: -5.3394, width: 16.685, depth: 10.3288 }` art plane.
- Adding a layout requires all four: a catalog entry, `conveyorLayouts.<id>` defaults in src/scene-tuning.js, an option in src/scene-editor.js `CONVEYOR_LAYOUT_OPTIONS`, and the art path in src/mechanism-resources.js `MECHANISM_RESOURCE_MANIFEST` (export whitelist — missing it silently substitutes a 1-byte placeholder in packaged builds). A layout that a stitched session may select must also be listed in src/playable-session-config.js `CONVEYOR_LAYOUT_IDS`.
- scripts/extract-unity-conveyor-layouts.mjs: reads direct/nested Unity spline overrides, merges DualQueue5 with ConveyorBelt6, normalizes queues left-to-right, and regenerates the catalog/inspection JSON.
- src/scene-view.js owns selected-layout rendering; src/scene-tuning.js owns selected/per-layout editor transforms; src/level-data.js retains legacy DualQueue2 fields for compatibility.
- Imported spatial packages are discovered from `artifacts/spatial-conveyors/*.json` by the Vite editor service. They are selectable in development, render through the imported 3D spline/SplineMesh data, and use one direct entrance; point and entrance editing are still pending.
