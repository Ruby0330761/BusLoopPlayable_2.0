# Browser Automation

这份文档只回答一件事：什么时候该上浏览器自动化，以及默认用什么。

## 默认推荐

默认优先使用 `Browser Use`。

官方入口：

- GitHub: `https://github.com/browser-use/browser-use`
- Docs: `https://docs.browser-use.com/`

一般不需要在这里写安装教程。AI 通常知道如何按当前环境完成安装；需要时直接按官方文档安装即可。

## 什么时候用

这些场景优先考虑浏览器自动化：

- 视觉布局和适配问题
- 点击路径或 CTA 问题
- 最终包交互异常
- 音频触发时机异常
- 需要截图、控制台日志、交互证据
- 需要复现“editor 正常但最终构建产物异常”的问题

这些场景不要默认上浏览器自动化：

- 纯构建报错
- 纯静态类型错误
- 纯 schema / 配置格式问题
- 纯脚本导出问题

## BusJam 游戏实践结论

在其他组的 BusJam 游戏实践里，浏览器自动化最有价值的用途不是“替代人工审查”，而是提前发现最终导出页的问题。

重点经验：

- 优先测最终构建产物，不要只测 editor 或 dev server。
- 优先保留截图、控制台错误、关键 DOM 状态、CTA 点击链路。
- 最适合拿来查：
  - loading 是否正常
  - CTA 是否按预期出现和触发
  - 引导 / 结束蒙层时机
  - 音频是否在首个用户交互后才启动
  - 最终导出页和编辑器预览是否表现不一致
- 它适合做前期自动调试，不适合代替真实平台上传和人工试玩。

## 推荐做法

- 先构建最终包，再用浏览器自动化打开最终产物。
- 必要时同时保留 editor 截图和最终包截图做对比。
- 验证 CTA、引导、结束态时，尽量把操作路径和结果截图一起留档。
- 如果问题已经明确是平台后台、广告容器或真实提审链路问题，浏览器自动化只能辅助，不是最终结论。
